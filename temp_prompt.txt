---------------------------------------------------------------------------------------------------------
Contexte
---------------------------------------------------------------------------------------------------------
NPone29 Cleaner est une application Windows en Python + customtkinter, entièrement en français.
Une page « Sauvegarde » existe déjà et fonctionne (sauvegarde manuelle) :

- app/core/backup.py : le moteur, sans interface.
  - plan_backup(sources, destination, mode, excludes, cancel, on_progress) -> BackupPlan.
    Analyse les dossiers ; rien n'est écrit.
  - run_backup(plan, cancel, on_progress, keep_full) -> BackupResult.
    Copie les fichiers. Le manifeste est écrit en dernier, donc une sauvegarde interrompue n'est jamais
    utilisée comme base.
  - Fonctions utiles : list_sets, check_destination (même disque physique, FAT32…), repository_for,
    prune, verify, restore.
  - Types : FULL / DIFFERENTIAL / INCREMENTAL.
  - Les fichiers sont copiés en clair dans <dest>\NPone29 Sauvegardes\<PC>\<date>_<Type>\<Libellé>\...
    avec un inventaire complet par sauvegarde.
- app/ui/pages/backup.py : la page, avec deux onglets (Sauvegarder / Restaurer).
  - Les réglages sont lus dans Settings : backup_sources, backup_custom, backup_destination, backup_mode,
    backup_keep_full, backup_last.
- app/utils/settings.py : réglages JSON dans %APPDATA%\NPone29Cleaner\settings.json.
  - Attention : Settings réécrit tout le fichier à chaque set().
- main.py : point d'entrée.
  - Options existantes : --debug, --selftest.
  - Le .exe (PyInstaller, NPone29Cleaner.spec) demande les droits administrateur au démarrage
    (manifeste uac_admin).
- app/utils/notify.py : notification Windows (icône de zone de notification, liée à une fenêtre hwnd).
- Tests : tests/test_backup.py (20 tests) et tests/conftest.py. Lancer avec `python -m pytest -q`.

---------------------------------------------------------------------------------------------------------
Objectif
---------------------------------------------------------------------------------------------------------
Ajouter une SAUVEGARDE AUTOMATIQUE. Le but est que, si le SSD lâche brusquement, la dernière sauvegarde soit
récente sans que l'utilisateur ait à y penser.

1. Mode sans interface : `NPone29Cleaner.exe --backup` (ou `python main.py --backup`).
   - Lit les réglages enregistrés (sources, destination, type, conservation) et lance plan_backup
     puis run_backup, sans ouvrir la fenêtre principale.
   - Décide lui-même s'il doit agir (voir point 2). Il ne fait rien si :
     - la sauvegarde n'est pas encore « due » ;
     - le disque de destination est absent (ex. disque USB débranché) ;
     - une autre sauvegarde est déjà en cours, que ce soit dans l'interface ou dans une autre tâche.
       Pour ça, utiliser un verrou : fichier de verrouillage dans %LOCALAPPDATA%\NPone29Cleaner, ou mutex
       Windows.
   - Écrit son résultat dans un fichier SÉPARÉ, %APPDATA%\NPone29Cleaner\backup_status.json, et pas dans
     settings.json. Sinon l'interface ouverte et la tâche s'écraseraient mutuellement leurs réglages.
     Contenu : dernière tentative, dernier succès, type, nombre de fichiers, erreurs, « disque absent
     depuis ».
   - L'interface lit ce fichier (et backup_last) pour afficher l'état.
   - Notification Windows en fin de sauvegarde : succès bref, ou échec / fichiers non copiés.
     Prévoir aussi un rappel si le disque est absent depuis plus de N jours.
     notify.WindowsNotifier a besoin d'un hwnd : créer une fenêtre Tk cachée, ou une autre solution
     simple et fiable.
   - Code de sortie non nul en cas d'échec.
   - Journal dans le log habituel.

2. Planification : une tâche du Planificateur de tâches Windows.
   - Approche recommandée : une tâche « NPone29 Cleaner - Sauvegarde » déclenchée à l'ouverture de
     session ET toutes les heures. Le mode --backup décide ensuite si une sauvegarde est due, selon la
     fréquence choisie et la date du dernier succès.
     Avantage : un portable éteint à l'heure prévue, ou un disque branché seulement de temps en temps,
     est quand même sauvegardé dès que possible.
   - Fréquences proposées : chaque jour, chaque semaine, ou « à chaque branchement du disque » (= dès
     que le disque est présent et que la dernière sauvegarde date de plus de X heures).
   - Option : une sauvegarde complète toutes les N semaines, et incrémentales/différentielles entre deux.
     Mettre cette logique dans une fonction pure, testable.
   - Création et suppression via schtasks.exe avec un fichier XML (/Create /XML). Le XML permet :
     - StartWhenAvailable ;
     - pas d'arrêt sur batterie ;
     - MultipleInstancesPolicy = IgnoreNew ;
     - ExecutionTimeLimit raisonnable.
   - Commande lancée : sys.executable si l'application est compilée (sys.frozen), sinon pythonw.exe +
     main.py (mode développement).
   - IMPORTANT : le .exe exige l'élévation. Il faut donc une tâche « Exécuter avec les autorisations
     maximales » (RunLevel HighestAvailable), créée depuis l'application lancée en administrateur.
     Sans droits admin, le dire clairement dans l'interface (comme le bandeau existant) au lieu
     d'échouer en silence.
   - Vérifier que la tâche s'exécute dans la session de l'utilisateur, pour qu'elle ait accès à ses
     dossiers et à ses lecteurs réseau. LogonType InteractiveToken.
   - Prévoir le cas d'un lecteur réseau mappé (Z:) invisible pour une tâche élevée : conseiller le
     chemin UNC (\\NAS\partage).

3. Interface : nouvelle carte « 4. Sauvegarde automatique » dans l'onglet Sauvegarder de
   app/ui/pages/backup.py.
   - Interrupteur Activer / Désactiver, qui crée ou supprime la tâche.
   - Fréquence ; type pour les sauvegardes automatiques ; option « une complète toutes les N semaines ».
   - État lisible :
     - « Activée — dernière sauvegarde automatique : … — prochaine : dès que le disque E: sera
       branché » ;
     - « ⚠ Disque absent depuis 9 jours » ;
     - « ✕ Échec : … ».
   - Si la destination ou les dossiers changent, la tâche utilise automatiquement les nouveaux réglages
     (elle les relit à chaque exécution). Il n'y a donc rien à recréer, sauf le chemin de l'exe.
     Si l'exe a été déplacé : détecter que la tâche pointe vers un autre chemin et proposer de la
     réparer.
   - Le TipBox « Dernière sauvegarde » existant doit refléter aussi les sauvegardes automatiques.
   - Optionnel : afficher l'état de la sauvegarde sur le Tableau de bord (app/ui/pages/dashboard.py).

Contraintes
---------------------------------------------------------------------------------------------------------
- Interface et messages en français, ton simple pour un utilisateur non technicien. Ne rien activer sans
  l'accord de l'utilisateur.
- Ne pas casser la sauvegarde manuelle. Réutiliser le moteur backup.py ; ne pas dupliquer la logique.
- Code testable : séparer les fonctions pures (échéance, génération du XML, construction de la commande,
  lecture/écriture de backup_status.json, verrou) des appels Windows.
- Ajouter des tests dans tests/test_backup.py ou un nouveau tests/test_backup_schedule.py.
  Ne PAS créer de vraie tâche planifiée dans les tests.
- Mettre à jour le README : tableau des fonctionnalités, section Sauvegarde, « Pistes pour la suite » (y
  retirer la sauvegarde planifiée).
- Passer la version à 1.3.0 dans app/config.py ET version_info.txt, si ce n'est pas déjà fait.
- Vérifier :
  - `python -m pytest -q` ;
  - `python main.py --selftest` ;
  - `python main.py --backup` sur un dossier de test ;
  - la page, en vrai, en thème sombre et clair.
  Pillow n'est pas installé : faire les captures avec PowerShell
  (System.Drawing.Graphics.CopyFromScreen), comme pour la page Sauvegarde.
- Ne pas laisser de tâche planifiée de test sur le PC à la fin.
